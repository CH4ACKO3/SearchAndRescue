# 随机场景与权重搜索

真实引擎执行与并行 TPE 搜索见 [实机入口](ENGINE.zh-CN.md)。以下说明对应保留的离线模拟器。

第一版是离线、可重放的医疗轮次模拟器，用来筛选值得在 RimWorld 中验证的参数假设。执行一个伤口的治疗后释放患者所有权，再调用生产代码的 `WeightedBipartiteMatcher` 全局匹配；连续性衰减直接引用 `TreatmentContinuityRules`。

## 运行

在模组仓库根目录运行，需要 .NET 8 SDK：

```powershell
dotnet run --project Tools/SchedulerOptimizer -c Release -- self-test
dotnet run --project Tools/SchedulerOptimizer -c Release -- search --seed 20260906 --scenarios 60 --iterations 100 --output artifacts/optimizer/20260906
dotnet run --project Tools/SchedulerOptimizer -c Release -- replay artifacts/optimizer/20260906/worst-regression.case.json artifacts/optimizer/20260906/replay.json
```

`--scenarios` 是每个集合的场景数，建议取 6 的倍数。上述命令生成 180 个场景；100 次候选评估发生在训练集。相同种子、参数、工具版本和 .NET 运行时可复现相同结果。所有输入场景写入 `scenarios.json`；场景和参数可以独立复制给 `replay`，不依赖原搜索过程。

## 场景与时间推进

| 场景族 | 主要压力 |
| --- | --- |
| balanced | 2–5 名医生、5–12 名伤员，位置、技能、速度、出血与伤口数随机 |
| overload | 1–2 名医生、有限药品、积压患者 |
| remote_stock | 药库远离医生和伤员，考察取药绕路 |
| late_critical | 800–2200 tick 后出现高失血、多出血伤口患者 |
| infection | 感染随时间恶化，与出血和普通伤口竞争处理机会 |
| external_owner | 部分患者暂由外部任务占用，1200 tick 后释放 |

每个场景固定推进 12000 tick，步长 30 tick。行动耗时包括行走与一轮治疗；治疗期间持续失血、感染恶化，并可发生死亡。医生每轮结束后重新匹配。共同药库逐份预约，用完后回退至徒手方案，保持一次任务一种物资。所有随机输入在场景创建时确定，候选参数不会改变后续随机数序列。

## 固定评分

单场景分数为 `1000 − cost`，可能为负。评分系数固定，搜索只调整调度权重。

| 成本项 | 系数及归一化 |
| --- | --- |
| 死亡 | 1000 × 死亡人数 / 总伤员数 |
| 存活但未完成处理 | 150 × 未完成人数 / 总伤员数 |
| 伤情累计负担 | 100 × 失血与未治疗感染的时间积分 /（总伤员数 × 时长） |
| 首次有效治疗延迟 | 50 × 所有伤员等待时间 /（总伤员数 × 时长）；未被治疗和死亡者按观察结束截尾 |
| 更换医生 | 10 × 换医次数 / 完成轮数 |
| 行走 | 2 × 总距离 /（总伤员数 × 100） |
| 药耗 | 2 × 使用药品数 / 总伤员数 |

出现重复所有权、侵犯外部占用或负药品库存，场景得分为 -1e9，候选直接淘汰。选拔还要求每个场景族的总死亡人数不高于基线。该约束适用于场景族总数，单个场景仍可能退步，所以必须检查最差回放。

集合排名使用 `0.8 × 平均分 + 0.2 × 最差场景族平均分`。这样换医与节约药品的收益有明确上限，同时能看到群体救治表现与薄弱场景。无效操作、手动命令和 Job 参数是否正确仍需生产规则与实机测试验证；权重搜索无法修好 Maker 的重复止血带一类逻辑错误。

## 搜索与参数

采用有界随机探索和围绕当前最佳值的局部扰动。每四次候选有一次全范围探索，其余为参数范围 15% 的扰动。训练集前八个不同参数进入验证集，基线始终参与选拔。验证集确定唯一候选后，只评估一次保留测试集。

| 参数 | 搜索范围 | 与生产代码的关系 |
| --- | --- | --- |
| EmergencyRoute | 50–2500 | 起点 325，与 EmergencyMedicineRouteCost 默认值同量级 |
| FollowupRoute | 100–4000 | 起点 900，与 FollowupMedicineRouteCost 默认值同量级 |
| ContinuityScale | 0–4 | 乘在共享的已完成治疗连续性曲线上；生产默认倍率 1 |
| QualityScale | 0.25–3 | 乘在近似的伤情 × 医术收益上；生产代码目前没有此倍率设置 |
| DeadlineScale | 0–4 | 模拟器截止时间项倍率；生产 DeadlineWeight 的公式不同 |

训练、验证、测试种子分别从 seed、seed+10000、seed+20000 开始，各自最多 10000 个，不重叠。报告提供 1000 次配对 bootstrap 的均分差区间。只有测试集保持各场景族死亡约束、稳健分提高、区间下界大于 0，才标为 `candidate-for-game-validation`。否则明确输出 `no-validated-improvement`，候选也不会写入游戏设置。

重复查看测试集后继续针对它改模型或调搜索，会使它失去保留测试集的意义；下一轮确认应使用新种子或锁定的独立场景库。触及参数上下限会单独列入报告，供检查模型偏差或搜索范围。

## 产物

- `report.json`：基线、候选、集合与场景族分数、死亡数、配对差值、边界参数。
- `training-history.json`：全部训练候选及指标。
- `scenarios.json`：三个集合的完整输入。
- `test-metrics.json`：逐场景基线和候选指标。
- `worst-regression.case.json`：得分退步最多的场景与参数；即使所有场景改善，也输出改善最少者。
- `worst-regression.baseline.json` / `candidate.json`：相同场景的逐轮事件回放。
- `worst-absolute.case.json`：候选绝对得分最低的场景。

输出位于忽略版本控制的 `artifacts`，工具源码和设计说明保存在仓库中。

## 实机连接与覆盖范围

当前共用生产匹配算法与连续性曲线；伤情动力学、技能收益、直线距离、药品效果和可用时间属于显式的近似模型。药品暂仅提高本轮速度，普通伤口优先于感染处理；这些假设需要用实机轨迹校准。基线是默认量级的模拟器策略，分数不能解读为当前 SAR 在游戏中的实际得分。

本版尚未模拟床位撤离、护士分工、机体维修、墙体寻路、睡眠需求、手动指令中途插入、实际 MI/CE 器材 JobDriver 或运输中断。有限药品在匹配后逐份预约，库存不足时重新计算该医生的徒手选项，尚未重新求解资源约束下的全图最优匹配。

后续实机闭环按以下接口扩充：由相同 Scenario 描述生成独立测试地图与初始存档；每个参数组合重载同一初始存档；采集治疗效果、出血、任务开始/结束、预约和路径耗时；按固定评分产生 Outcome。先用这些轨迹校准离线模型，再对候选执行多存档回归。生产权重的变更需要逐项映射和验证，工具当前不会自动部署或重启游戏。
