# Search and Rescue 1.6 兼容性清单

更新日期：2026-09-06

兽耳屋勤工（`Moo.Hardworking.Kz`）：**部分兼容**。在勤工面板启用已解锁的战地救援及对应医疗/搬运工作即可加入，不要求动物救援训练。读取勤工优先级，遵守原生停工、跟随权限、交互冷却、强制夜间作息及疲劳限制。救援训练不能绕过工作禁用。概率工作模式暂不参与 SAR 自动调度。[18 项真实框架组件权限回归](../validation/2026-09-05-hardworking.json)通过；兽耳屋种族本体的完整 Job 流程尚未验证。

Hardworking animals 1.6（[工坊 933324235](https://steamcommunity.com/sharedfiles/filedetails/?id=933324235)）：**待实测**。它主要提高动物搬运频率，不属于兽耳屋勤工适配。根据公开描述和 SAR 现有动物救援通道，预计可共存，但本机未安装，未核对本体代码或实测。动物仍需学会救援并加入 SAR 才能搬运伤员，仅有搬运训练不会获得 SAR 送药或治疗资格。本机 Animals Logic 元数据将 `Daniledman.HardworkingAnimals` 列为不兼容，这是它们之间的冲突声明。

状态说明：

- **联动**：SAR 为该模组新增了专有救援阶段、人员通道或补给来源，而不只是避免冲突。
- **兼容**：SAR 会读取设置、识别工作或保护所有权，或双方可通过 RimWorld 标准接口稳定共存；不新增一整组玩法机制。
- **部分兼容**：基础功能可以共存，但仍有明确未接管的重叠区域、缺少本体实测，或可选适配器未能正确加载。

这里的状态描述 SAR 自身的支持范围，不代表表中第三方模组彼此兼容。游戏内兼容性表还会根据模组是否启用及可选适配器是否成功加载，动态显示“未启用”或把状态降为“部分兼容”。

| Emergency Transfusions | 联动 | 使用原生单包输血 Job，支持伤员、医生、地图或驮兽携带的血原包。 |
