# 多模组组合处理：实现与验证

2026-09-08。兼容面板继续使用原有的一对一清单。

后续已完成 [Gabs 18 模组可视游戏实测](2026-09-08-gabs-combinations.zh-CN.md)，补充真实 CE 消耗/补货、MI 输血与多伤员流程。下文无图形探针结果保留为此前批次的证据。

## 已实现

- **用药策略统一**：SAR 同时检测到 CYM 与 SM 时，预算及候选使用 CYM；不经过可能被多个选药模组覆盖的原版查找器。CYM 原生接口已经限制普通个人用药，并允许单伤手动覆盖，SAR 保留这一语义。SM 单独作为选药提供者时，读取其真实本轮伤口列表、单伤设置、原始用药恢复值及 Pharmacist 建议，预算与候选使用相同许可。签发普通包扎/CE 稳定任务时再次检查已选药品，失效时返回重算而不偷换已声明药堆。
- **复苏资源协调**：同一种物资被多个复苏提供者使用时，现场保护预算取替代需求的最大值，独立用途仍相加。已有一种可用复苏物资在患者旁时，先使用它，再重算下一次补给，避免同时囤积全部替代品。保留 MI 和直接输血各自的候选，因为它们支持的库存位置可能不同；同一实际药堆存在可执行 MI 血液处理时优先该候选。继续使用原生 MI 的盐水安全、失血及血液稀释判断，没有将不同液体硬换算成相同疗效。
- **动态血液物资**：MI 的 Biotech 血原联动设置改变后，SAR 重新读取当前血液物资类型；旧类型的已选血液任务会在签发时被拒绝，随后重新规划。
- **外部交接**：当注册医疗设施或外部 Lord 持有患者时，SAR 的治疗、运输和看守门控与协调器一起退让。提供者释放后恢复门控，原标记仍保留。这里使用设施/Lord 所有权，不将任意外部工作都当成全面解除 SAR 门控的理由。
- **RH2 + SM**：CE 未启用且患者躺卧时，RH2 无药急救可以作为候选与 SM 共存。RH2 带药路径仍保留原条件，避免将其多剂取药流程直接套用 SM 的单轮物资声明。

以上处理限于 SAR 管理的工作路径；没有修改第三方模组本体，也没有把 CYM 与 SM 的全游戏互斥问题宣称为已全面解决。

## 验证

Release 构建为 0 警告、0 错误。离线回归通过：92 项生产规则（含新增 7 项共享预算检查）、9 项治疗连续性检查、40 个调度场景、200 组随机图。

最终额外启用 CYM 的配置通过 19 项游戏内接口/所有权检查，含保留直接输血取药备选的修订。[结构化证据及 DLL 哈希](../validation/2026-09-08-combination-fixes.json)。此前未启用 CYM 的配置也通过单伤策略与血液接口检查，但不把早期批次当作最终全部改动的重复验证。无图形进程日志含 Unity shader 不支持提示，不属于医疗回归失败。

实机使用独立 savedatafolder、独立 SAR 测试副本和原生 RimWorld 1.6.4871，未改玩家当前模组配置或存档。测试自动生成一次性地图，检查完成后退出。

两种配置分别为 CE + SM + MI + Hemogen Direct，以及额外加入 CYM；均包含 Harmony、Core、Biotech 和 SAR。测试实际调用第三方单伤设置、SAR 需求/选药/任务构造与 MI 原生需求接口。首批验证发现测试夹具未正确设置 MI 的 ref 属性，修正为设置其真实 backing field 后重新验证；以最终证据为准。

设施交接检查临时将真实普通床类型注册为设施，以验证患者实际卧床、生产所有权查询、三个门控退让及释放后的恢复。这是注册边界验证，不是 MedPod 或 Trauma Team 本体全流程测试。

复跑工具：[Run-CombinationProbe.ps1](../../Tools/Run-CombinationProbe.ps1)。要求新建的 RuntimeDir 位于游戏 Mods 目录，SaveData 也必须是新目录；使用 `-ChooseYourMedicine` 添加 CYM。工具不会自动安装缺少的第三方模组。

## 范围

本轮没有新增救护车专用储备设置、改变 CE 库存最低保留量、接管车内患者，或增加机器人维修零件的载具运输。现有 VF 取货与改变持有者时的恢复机制继续沿用。上述功能属于此前报告中的扩展联动方案，需另行实现并做完整 Driver 测试。

本轮实机结果是接口与所有权边界验证，尚未完成新的 150,000 tick 多模组长跑、Pharmacist 本体专项、RH2 原生无药 Driver 全程、真实 Trauma Team/MedPod 交接或 VF 四方并发搬运测试。
