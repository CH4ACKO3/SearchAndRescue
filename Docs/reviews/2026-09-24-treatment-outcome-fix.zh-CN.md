# 空治疗成功判定修复与 alpha.15 发布验证

## 审查后落实的边界

- DoTend 前记录当时可治疗的伤口与治疗计时、严重度，返回后检查伤口消失、可治疗状态变化、治疗时间延长或同步治疗造成的严重度下降。只有实际变化才调用 NotifyTreatmentCommitted。无需原方法执行，也无需药品堆叠数减少，因此保留替换式前缀和多次使用医疗包。
- 记录 Job 的引用、定义与 loadID，原调用期间任务已被结束或对象池复用时不把结果记给新任务。异常路径不记成功，原有 finalizer 恢复急症过滤作用域。
- 原生 TendPatient 和 BCD 使用实际提交数，普通跨 tick 失血自然恢复不再授予包扎成功。最后一轮无效果会覆盖先前成功轮数的退出判定；已无需治疗的患者仍正常退出。
- 空原生轮使用 endAfterTendedOnce，聚合 BCD 在下一监控 tick 退出，不在 DoTend 回调里递归结束任务。仍有同阶段需求则渐进退避，阶段已变化则让其它阶段正常调度。不会因空治疗刷新成功亲和。
- 急救、补治候选筛选，待执行方案验收、任务创建采用同一阶段规则；补治评分显式传递 FollowupTreat，避免默认 Treat 过滤。输血等专用干预不被普通包扎过滤误删。
- 原生 FinalizeTend 在读条后再检查急症资格；已稳定的受限任务在调用 DoTend、技能经验和第三方记账之前退出。保留 DoTend 内最终防线，防止第三方直接调用绕过原生 toil。

此次聚焦 SAR 管理的包扎及其完成判定，没有试图把第三方所有专用干预的成功条件重写为普通伤口治疗，也不接管无 SAR 声明的手动任务。玩家此次存档的具体触发条件仍未提供，不能保证所有表现为读条循环的问题都由此修复。

新增检查包括：SAR 急症过滤跳过时计数为零；人为跳过治疗不消耗药且不假成功；连续空轮退避次数递增；跨 tick 失血变化不证明治疗成功；替换前缀实际包扎但药物数量不变仍认成功；疾病尚有治疗计时却需重新包扎；异常后作用域恢复；阶段资格及补治评分；已稳定 finalizer 不调用 DoTend；真实 JobDriver 空轮结束、调度器退避、提供者恢复后重新成功治疗。

故障注入只在显式 capture quicktest 中临时安装，并在 finally 移除。完整俘虏流程由自动调度推进；空轮 JobDriver 检查另显式注册一次受管任务，以确保检查的是 SAR 的失败处理，未把非受管原生医生工作算作受管测试。

## 夹具修订与限制

- 部分工坊文件存在磁盘但游戏未将其列为可用模组。初轮 BCD、CE、Death Rattle 未实际载入的运行不作为对应兼容验证；将原包复制到隔离测试可见的本地 Mod 目录，核实实际加载列表后重跑。
- AUR 早期有一个普通治疗样本在 1200 tick 上限时仍在读条，测试窗口扩大到 6000；正式六种医疗包均通过。生产治疗时长未变。
- CE 旧断言只数医生库存与携带物，可能漏掉任务结束后落地的剩余药物；改为测试地图、库存、携带物的总量守恒。alpha.14 对照和新版本都可完成止血；最终新版本药物总量 33→32。
- 新 finalizer 夹具起初用 Job 对象引用判断退出，遇到对象池复用后误报，改用 loadID；有效结果为调用次数 0、提交次数 0。
- 有一次早期随机 Core 俘虏场景止血后未送床，未保存可重载的故障存档，不能确认具体原因。已保留该失败结果，补充失败时的调度快照诊断；最终 Core 场景及追加三次随机重跑均完整通过。没有据此宣称所有运输边界已被证明正确，也没有顺便改动运输逻辑。

生产逻辑在最终基础/组合/CE 与 BCD/AUR/Rimkit 通过批次中相同；后续差异仅为诊断的对象池断言、药品统计和失败快照。证据和各运行 DLL 哈希位于 Docs/validation/2026-09-24-treatment-outcome-fix。
